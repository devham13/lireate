# Дизайн страниц /patent и /patent_prom_obr — LIREATE Light V4

Две устаревшие страницы переоформлены в духе главной: белая юридическая тема, красный #e32020, синий #2155b9, карточки, этапы, FAQ и вертикальные фотографии владельца. Левая навигация PHP-CMS и общая шапка остаются. Верхние пункты («Об услуге», «Что защищаем», «Страны», «Этапы», «Кейсы», «FAQ») являются якорями **этой страницы**, без цифр. На мобильном используется действующий бургер CMS.

- `/patent` — `patent-inventions.webp`, сделан вертикальный кадр из **первого загруженного фото** и отражён горизонтально, чтобы человек смотрел влево.
- `/patent_prom_obr` — `patent-industrial-design.webp`, вертикальный кадр из **второго фото** с палитрой.

Сохранены смысловые блоки существующих страниц: направления, страны, этапы, оценка охраноспособности и реальные кейсы ВК. Нет выдуманных кейсов и гарантированного исхода патентования. Некоторые устаревшие утверждения старого текста (например, «единый патент ЕС на 38 стран», «регистрация уже завтра» и «возврат 110%») не перенесены как проверенные юридические факты. Уточнить тексты с патентным специалистом до публикации.

Форма «Оставить заявку» **не создаёт новой серверной логики**: использует существующий `.js-modal-form` и атрибуты CMS. Обязателен smoke-test на реальном сайте (PHP + JS обработчик), сохранение целей Яндекс.Метрики, консент-форм и ссылок на политику. `title`, `description`, `canonical`, schema, остальную SEO-голову оставляет действующая CMS, не создаёт дублей.

## Установка на REG.RU

В GitHub `template/main.php` отсутствует, он на хостинге; installer использует существующую ветку `$temp['apsw']` CMS и обслуживает оба route slug, не изменяя данные БД.

**Dry-run:**

```bash
python3 scripts/lireate_patent_light_v4_install.py --docroot "$LIREATE_DOCROOT" --backup-root "$HOME/lireate-autopub/backups/patent-light-v4"
```

Нужен `template/main.php` с anchor `<div class="page_container">` и веткой `if($temp['apsw'])` или `elseif($temp['apsw'])`. Иначе installer **останавливается**, не делает опасный fallback. Проверить diff и PHP ветки.

**После согласования и проверки:**

```bash
python3 scripts/lireate_patent_light_v4_install.py --docroot "$LIREATE_DOCROOT" --backup-root "$HOME/lireate-autopub/backups/patent-light-v4" --php-bin php --apply
```

При наличии нестандартного PHP использовать актуальный бинарник из окружения. Installer делает backup **вне DOCROOT**, атомарную запись и `php -l`, возвращает `APPLIED backup=...` или откат при ошибке. Ручной откат:

```bash
python3 scripts/lireate_patent_light_v4_install.py --docroot "$LIREATE_DOCROOT" --rollback /FULL/PATH/TO/BACKUP
```

## Smoke-test и вопросы перед merge

1. URL `/patent`, `/patent_prom_obr` отвечают 200, на каждом **один H1**, корректная CMS meta-информация, прежние canonical и URL.
2. Левое меню раскрывается; верхнее не добавляет вторую навигацию на мобильном; фото грузятся и не зеркалятся повторно.
3. Страницы при ширинах 390/768/1280/1440 без горизонтального overflow; sticky и active links корректны.
4. `.js-modal-form` открывает старую модалку; форма передаёт данные, цели Метрики, согласия на ПДн и ссылки на политику остаются корректными.
5. Проверить перечень международных процедур, сроки, квалификацию и формулировки маркетинговых обещаний с патентным юристом.
6. На боевом сайте ничего не менять без утверждения PR и согласования внедрения. Изменения только в двух маршрутах и общих двух ассетах для этих маршрутов.
