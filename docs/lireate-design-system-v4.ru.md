# LIREATE Light V4 — обязательная единая дизайн-система сайта

Дата решения: 25.11.2026. Относится **только** к lireate.ru (патентное бюро / юридическая компания). Этот документ — канон для главной, действующих и новых услуг, «Патентных задач», списка и страниц статей блога, команды, кейсов и общих страниц CMS. Старые тёмные шаблоны считать legacy.

## Источники согласованного дизайна

- Главная — design-proposals/lireate-light-v4/home/index.html (локальный HTML-прототип, noindex только для preview).
- Детальная услуга — pages/services/registraciya-tovarnogo-znaka/index.php с белым v3 и Light V4 overlay, **контент и юридически точные тексты не заменять краткими копиями из hero**.
- Референс содержания/композиции юридического сайта — https://tovarnyj-znak.ru/patent-poleznaya-model (построение секций и ясная информационная иерархия; не копировать чужие изображения/код).
- Команда — круглая карусель https://jiro.build/components/team/team-01-pixa по принципу, не дословной реализации.
- Динамика — https://mayai.ru (тип анимаций, не копировать исходный JS/CSS): staggered reveal, active tabs, counters, sticky header, hover и FAQ.

## Цвета, пропорции, правила

| Токен | Значение | Применение |
| --- | --- | --- |
| white | #FFFFFF | Главный фон сайта и основной фон всех страниц |
| ink | #1F212C | Заголовки, основной контент, меню |
| red | #E32020 | Брендовые акценты, активная линия шага, основные CTA |
| red-hover | #C71313 | Hover основной кнопки |
| blue | #3A86FF | Фокус, ссылки, вторичные CTA, интерактивные состояния |
| blue-soft | #F3F8FF | Только панели раскрытых шагов, меню, hover; не сплошной фон |
| line | #DCE8F7 | Тонкие границы и разделители |
| body | #52637B | Второстепенный текст, но не заголовки |

Красный/синий взяты по видимому стилю текущей главной; значения приближённые до проверки исходных переменных CSS в CMS. Приоритет у согласованного логотипа и CSS бренда, если есть точные токены. Никаких тёмных секций, сплошных серых заливок, случайного фиолетового/градиента ради украшения. Допускаются холодные светлые голубые тени и локальные полупрозрачные мотивы с контрастным текстом.

Типографика: Inter/Manrope (fallback system-ui). Hero H1 clamp(36px, 4.3vw, 64px) с 1.05 line-height; H2 clamp(30px, 3.6vw, 50px). Текст 15–17px, line-height ≥1.6. Max width 1120–1280px, desktop grid 2/3 колонки, mobile 1. Не уменьшать контент до нечитаемых «дизайнерских подписей».

## Ключевые блоки

1. **Hero:** один H1 + конкретное юридическое обещание без ложных гарантий + CTA к существующей форме/контактам + реальные лица специалистов, если есть разрешённые фотографии.
2. **Услуги:** на главной 4 карточки — товарный знак (®), патент (механика/чертёж), договор (§/документ), программы ЭВМ (код). Белые карточки, голубая графика на 8–18% непрозрачности. Hover: подъём ≤5px, красная линия и движение символа, focus-visible аналогичен. Текст не перекрыт рисунком.
3. **Как работаем:** интерактивная последовательность из 3 шагов для общей главной. Нажатие раскрывает фактические действия Лирейт, сведения от клиента, результат этапа. Плавное раскрытие, красная шкала прогресса, aria-expanded/aria-controls и клавиатура. На странице регистрации свой детальный четырёхшаговый маршрут — **не сокращать и не подменять**.
4. **Команда:** круглые фотографии сотрудников с lireate.ru, настоящее ФИО/должность, carousels с кнопками, filter (если нужен). Альтернативный текст, preload только первого важного фото, остальные lazy. Не использовать стоковые лица.
5. **Кейсы/портфолио:** проверенные факты, работающие ссылки, фото/документы только с правом использования. Нет придуманных цифр, исходов, отзывов.
6. **Цены:** отдельно услуги и пошлины; для регистрации ТЗ на странице сохранены 35 000 ₽ пошлины базового цикла и подробная разбивка, если подтверждена. Не смешивать с стоимостью услуг на главной (от 30 000 ₽) и не утверждать гарантии выдачи свидетельства.
7. **Блог:** белая редакционная сетка, сохранение всех статей из MySQL, обложки, авторы, даты, TOC, рубрики, пагинация, перелинковка, метаданные Article/BlogPosting, публичные URL и canonical. Новые статьи автоматически используют оболочку v4; не переписывать full_story только ради дизайна.
8. **Заявки:** в продакшене сохранить рабочие формы CMS, валидацию, обработчики, антиспам, метрику, правовые согласия. Никаких фальшивых кнопок, ведущих на пустую форму. Ссылки о ПДн: /private_data и /politika_konfidencialnosti.

## Интерактив и доступность

- Scroll reveal 450–650 мс, stagger 60–90 мс; не скрывать контент без работающего JS.
- Hover 250–400 мс, transform и opacity предпочтительнее layout shifts.
- Для вкладок aria-selected, tablist/tab; для accordion native details/summary или корректное состояние aria-expanded.
- prefers-reduced-motion:reduce — убрать анимацию, сохранить все тексты и управление.
- Фокус видим: контур #3A86FF, min tap 44×44, контраст WCAG AA, клавиатурные стрелки там, где применимо.
- Не использовать тяжёлое видео как обязательный контент, не ставить анимацию на каждую букву H1, не анимировать ключевые юридические оговорки.
- Показатели, цены и сроки — без выдуманного анимированного прироста; счетчик к фактическому значению с fallback текстом.

- template/css/lireate-light-v4.css, template/js/lireate-light-v4.js — для общей обёртки CMS, подключить после legacy CSS и использовать класс body.lireate-theme-light-v4.

- pages/blog/_shared/lireate-blog-light-v4.css, template/page/news/lireate-blog-light-v4.css — overlay списка и статьи, после legacy CSS.

## Правило внедрения по всем страницам

1. Новый стиль создаётся и проверяется в отдельной ветке с PR. Не merge из этого документа автоматически.
2. Cursor должен адаптировать основной CMS header/footer (исходники на REG.RU/репо), загрузить общие CSS/JS и проставить body.lireate-theme-light-v4 на согласованных шаблонах. Только после карты зависимостей; не добавлять глобальный CSS ко всем страницам слепо (есть независимые лендинги).
3. Для услуг: прогон migration --check, после backup --apply; синхронизация shared; lint; проверка каждого slug.
4. Для блога: sync template, test render article/list, не трогать публикацию новостей или DB без необходимости.
5. Для разнородных общих страниц (команда, контакты, документы, патентные задачи): подключить общие токены и переработать локальные CSS отдельно. Требуются реальные проверки; одного импорта CSS может быть недостаточно.
6. Пользователь разрешил подготовить GitHub и применить изменения через Grok/Cursor; **предварительный PR не считается фактом публикации**. После интеграции нужен отдельный PR, screenshots и проверка форм/SEO, затем штатный деплой/rollback согласно существующему процессу.

## SEO / юридические требования (не нарушать)

- Не менять существующие URL/canonical, robots, sitemap, 301, микроразметку, title/description, H1 и рабочие внутренние ссылки без SEO-ревью.
- Никогда не переносить preview meta robots noindex,nofollow в боевую главную или услугу.
- Не удалять SEO-тексты ради укороченного дизайна; длинные материалы оформлять сеткой и оглавлением.
- Проверить Яндекс.Метрику, цели, consent, GDPR/152-ФЗ, доступность форм, Core Web Vitals.
- Любые юридические гарантии и цены подтверждать действующими условиями; при конфликте текстов — блокер для публикации, не придумывать.

## Definition of Done

Готово только если на staging проверены: главная, /registraciya_tovarnogo_znaka/, /news/, одна статья, одна типовая услуга, /team/ и /patentnye-zadachi/; мобильные 320/375/390px, планшет 768px, desktop 1280/1440px; screenshot before/after; формы, чат, CTA, индексируемость, доступность, Lighthouse, отсутствие console errors и безопасный откат. Отчёт и отдельный PR должны быть доступны владельцу.
