# Grok / Cursor — установить LIREATE Light V4 (не путать с простым копированием HTML)

## Исходники в ветке

- design-proposals/lireate-light-v4/home/index.html — последняя главная (с интерактивными 3 этапами и тематическими hover-карточками), **только референс/preview**;
- pages/services/registraciya-tovarnogo-znaka/index.php — действующая подробная SEO-страница с опциональным стилем v4;
- docs/lireate-design-system-v4.ru.md — единый утверждённый дизайн;
- template/css/lireate-light-v4.css и template/js/lireate-light-v4.js — CSS/JS для общей оболочки PHP CMS;
- pages/blog/_shared/lireate-blog-light-v4.css — белый стиль статьи и списка;
- .cursor/rules/lireate-light-v4.mdc — правило для ВСЕХ новых страниц.

## Что делает Grok, управляя Cursor

1. Забирает PR с дизайном, изучает AGENTS.md, существующую CMS и настоящий код текущего index/главной. Делает backup и новую ветку интеграции.
2. Превращает home/index.html в рабочий шаблон именно текущей CMS: сохраняет разметку, реальные формы, события Метрики, consent, SEO-тексты, footer, навигацию, team photos, быстрый контакт, пути статей; не выкладывает самостоятельный index.html прямо в DOCROOT.
3. Подключает глобальные template/css/lireate-light-v4.css и template/js/lireate-light-v4.js *после* текущих стилей и только с body class lireate-theme-light-v4; обходит все CMS-шаблоны, показывает список URL и исключения.
4. Для услуги /registraciya_tovarnogo_znaka/ сохраняет полную действующую страницу, 4 этапа, юридические оговорки, формулы пошлин, отдельные цены услуг, кейсы VK, ссылки и 12 FAQ. Ничего не заменяет короткими текстами главной.
5. Для остальных услуг сначала python3 scripts/lireate_light_v4_migrate.py (dry-run), после ревью python3 scripts/lireate_light_v4_migrate.py --apply, затем python3 scripts/lireate_service_sync_shared.py. **Не запускать в продакшене или CRON.** Проверить lint для каждой услуги.
6. Для блога python3 scripts/lireate_blog_sync_template.py и python3 scripts/lireate_blog_lint.py; проверить на staging /news/ + одну опубликованную статью и несколько рубрик. Отдельное хранилище lireate-news/MySQL не трогать ради CSS.
7. Для остальных страниц (команда, кейсы, патентные задачи, контакты, документы) пройти по CMS-шаблонам, добавить token styles отдельно с тестами, не перекрывать чужие сложные формы. При отсутствии файла исходника на GitHub — включить в список блокеров, не выдумывать путь.
8. Тесты: PHP 5.6 lint, service lint, blog lint, a11y, keyboard, screen widths 320/375/390/768/1280/1440, Core Web Vitals, формы и цели Метрики, корректный текст, canonical/noindex/JSON-LD, изображения/авторы, реальный max/telegram CTA, отсутствие JS errors.
9. Отдельный интеграционный PR со скриншотами до/после и точным списком изменений + команды отката. Не смешивать референсный PR и продакшен-PR.
10. После одобрения владельцем merge штатным способом, затем на REG.RU проверить ход CRON, исправность главной и услуги, блога и всех новых шаблонов. Отчёт с реальными URL, временем и статусом публикации; без выдуманного «готово».

## Особая осторожность

Превью главной имеет meta robots noindex,nofollow — он должен быть удалён из продакшен-реализации и не попутно из SEO-функций. Нельзя скрывать статьи или индексируемые абзацы анимациями. Нельзя объявлять «оплату за результат» гарантией государственной регистрации: итог зависит от Роспатента.

## Критерии готовности

Все новые страницы и статьи получают Light V4 автоматически из правил и шаблонов; все существующие страницы из согласованного списка переведены на белую систему; screenshot сравнение, формы/SEO/аудит зелёные; владелец подтвердил публикацию.
