# SEO-инструменты LIREATE

## Что подключено

| Инструмент | Размещение | Назначение |
| --- | --- | --- |
| Marketing Skills | `.cursor/skills/` | SEO-аудит, структура сайта, редактура, микроразметка, AI-поиск и контекст проекта |
| SEOnaut | Docker Compose на отдельном Linux VPS | Обход сайта, ссылки, редиректы, метаданные и заголовки |
| Unlighthouse 0.20.0 | GitHub Actions, Node.js или Docker на VPS | Лабораторные проверки Lighthouse, JSON и HTML-отчёт |

Marketing Skills сохранены в репозитории вместе с ресурсами. Cursor обнаруживает их
при открытии актуального проекта. Устанавливать весь сторонний маркетинговый плагин
поверх офиса LIREATE не требуется. Правило `.cursor/rules/lireate-seo-tools.mdc`
связывает новые навыки с существующими SEO-ролями. Основной пайплайн услуг из
`AGENTS.md` сохраняется.

Источник и контрольные суммы копий: `marketing-skills.lock.json`.
Лицензия MIT: `MARKETING-SKILLS-LICENSE`.

## Где запускать

SEOnaut требует отдельного Linux VPS с архитектурой **amd64**, Docker Compose v2
и Python 3. На общем PHP-хостинге REG.RU этот Compose-стек не запускается.
Доступ к CMS и MySQL рабочего сайта инструментам не нужен: они читают публичные URL.

Unlighthouse использует Node.js >=22.18.0 и Chromium. В Docker они включены в образ.
Начальный ориентир для VPS: 2 CPU, 4 ГБ RAM и место для отчётов; фактический расход
зависит от числа и сложности страниц. Проверки Lighthouse выполняются по одной.

## Запуск Unlighthouse через GitHub

В репозитории откройте **Actions → LIREATE live SEO audit → Run workflow**.
Доступны три режима:

- `homepage` — главная страница;
- `priorities` — 8 URL: главная, услуги регистрации знака и патентования,
  статьи о регистрации бренда одежды, названии, логотипе и проверке знака;
- `sample` — до 25 URL из sitemap и обнаруженных ссылок, без динамической выборки.

После установки workflow первый запуск `priorities` происходит при его добавлении
в `main`. В дальнейшем ручной запуск; расписание не создаётся. Одновременно
выполняется один аудит, страницы проверяются последовательно. Доступ к хостингу,
CMS, секретам и базе сайта не требуется.

Результат: таблица в Summary запуска и архив `lireate-mobile-seo-<run_id>`
в Artifacts, доступный 30 дней. Архив включает `index.html`, JSON и исходные
отчёты Lighthouse. Для интерактивного просмотра распакуйте его и используйте
локальный HTTP-сервер, как в примере ниже. Это разовый лабораторный замер,
а не позиции сайта или полевые Core Web Vitals.

Если REG.RU отдаёт защитную страницу вместо сайта, проверка останавливается.
Капча и блокировка хостинга не обходятся. Факт ошибки запуска не означает,
что страницы сайта имеют низкие оценки.

## Запуск SEOnaut на VPS

Из корня актуальной копии репозитория:

```bash
bash tools/seo/start.sh
```

Скрипт создаёт `tools/seo/.env` с двумя случайными паролями и правами `0600`.
Повторный запуск сохраняет существующий файл и данные. Docker поднимает отдельную
базу `seonaut` и приложение. Образ SEOnaut закреплён по digest в `compose.yaml`.
Рабочая база Lireate не используется.

По умолчанию интерфейс слушает только `127.0.0.1:19000` на VPS.
Для просмотра со своего компьютера откройте туннель, подставив существующий
SSH-профиль сервера:

```bash
ssh -L 19000:127.0.0.1:19000 YOUR_VPS_ALIAS
```

Откройте `http://localhost:19000`, зарегистрируйте первого пользователя и добавьте
проект `https://lireate.ru`. У интерфейса есть штатная регистрация пользователей;
доступ извне следует предоставлять через VPN либо reverse proxy с авторизацией.
Если используется другой адрес интерфейса, задайте его в `SEONAUT_SERVER_URL`.

Проверка состояния и остановка без удаления данных:

```bash
cd tools/seo
docker compose ps
docker compose logs --tail 50 seonaut
docker compose stop
```

Пароли базы не меняйте в существующем `.env` без отдельной миграции: MySQL сохраняет
пользователей в томе при первом запуске. Команду `down -v` для обычной остановки
не используйте — она удаляет базу аудитов.

## Проверка Unlighthouse через Docker

Сначала проверить одну главную страницу:

```bash
bash tools/seo/audit.sh smoke
```

Затем запустить обход с лимитом 400 страниц:

```bash
bash tools/seo/audit.sh site
```

Отчёты сохраняются в `tools/seo/unlighthouse/reports/smoke/` или `reports/site/`.
У полного обхода включены sitemap, robots.txt и обнаружение ссылок; динамическая
выборка отключена. Лимит в 400 страниц можно увеличить в конфигурации, если сайт
вырос. Приватные разделы и URL с параметрами исключены. Запуск ручной,
расписание не создаётся.

HTML-отчёт можно посмотреть через локальный сервер на машине, где лежат результаты:

```bash
python3 -m http.server 19001 --bind 127.0.0.1 --directory tools/seo/unlighthouse/reports/site
```

Для просмотра с VPS добавьте второй SSH-туннель на порт 19001.

## Локальная установка Unlighthouse без Docker

```bash
cd tools/seo/unlighthouse
npm ci
npm run check
npm run audit:smoke
npm run audit
```

Если Chromium уже установлен, задайте `PUPPETEER_EXECUTABLE_PATH` или `CHROME_PATH`.
При отсутствии браузера Unlighthouse может скачать совместимую версию сам.
В Docker используется системный `/usr/bin/chromium`.

Сканировать другой сайт можно через переменную `SEO_SITE_URL`; для Docker задайте
её в `.env`. `SEO_REPORT_DIR` позволяет выбрать отдельный каталог результатов.
Для каждого запуска без кэша используйте каталог отчёта Unlighthouse, а не папку
с документами или исходным кодом.

## Как применять результаты

1. Собрать технические факты SEOnaut и лабораторный отчёт Unlighthouse.
2. Передать нужные URL SEO-ролям Cursor с навыками `seo-audit`, `site-architecture`,
   `schema` или `copy-editing`.
3. Изменения страниц выполнять по правилам LIREATE и проверять по конкретному URL.
4. Позиции, показы, клики и спрос брать из Яндекс Вебмастера, Вордстата и Google
   Search Console. Балл Lighthouse не является позицией страницы в поиске.

Пример задачи в Cursor:

> Проверь страницу Lireate по seo-audit. Сопоставь выводы с HTML и отчётами из
> tools/seo/unlighthouse/reports. Подготовь исправления метаданных и внутренних
> ссылок по AGENTS.md. Для каждого изменения укажи URL и способ проверки.

## Проверка установки

```bash
python3 tools/seo/verify-install.py
```

Проверка сверяет наличие шести навыков и хеши исходных файлов, версию Unlighthouse,
локальный lockfile, конфигурацию и повторный запуск генератора `.env` в отдельной
временной папке. Это не заменяет запуск Docker на целевом VPS.

Текущие отчёты, `node_modules`, пароли и база аудитов не коммитятся.
